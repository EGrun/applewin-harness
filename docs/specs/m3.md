# M3 Spec — JSON-RPC server, agent audio, speed controls

**Status:** Draft. **Milestone:** M3 in `project.md`. **Decisions:** D3, D4, D8, D9, D10, D11, D12, D14 (new). **Builds on:** `docs/specs/m2.md`. **API reference:** `docs/api_spec.md`. This spec overrides it where they differ, and Part A's last task updates `api_spec.md` to match.

M3 has three parts, each with its own plan, built in this order on the branch `m3-jsonrpc-server`:
- **A:** the server, the session, and the agent and operator basics.
- **B:** agent audio and the new sound architecture (D14).
- **C:** speed controls (D11).

## Non-goals (later milestones)
- Checkpoints, `get_state_checksum`, `list_disks`, `export_disk` and `step_cycles` (M4).
- `get_text_screen` and shared-memory frames (M5, when the agent adapter needs them). For now, `allow_text_screen: true` and `shared_memory_frames: true` return `-32006`.
- Models other than `apple2ee`, a `video_refresh` of 50 (PAL), hard disks, and joystick 1. These all return `-32006`.
- Input rate limits and request size limits beyond framing (M6). Auto-repeat on held keys.
- More than one session per process (P6: AppleWin's sound state can't be reset in-process).

## Pass conditions
**Part A**
1. **M2 over the pipe.** A Python client using only the standard library does the following against `AppleWinHarness.exe --serve --headless`:
   1. `hello` as operator, then `create_session { disks: [DOS 3.3 master], run_mode: "stepped" }`.
   2. `step_frames { frames: 720 }`.
   3. `hello` as agent on a second connection, then `type_text { text: "PRINT 2+2\n", inter_key_delay_ms: 0 }`.
   4. `step_frames { frames: 60 }`.
   5. `get_frame { format: "PNG" }`.

   The PNG's pixel hash must equal `tests/golden/m2_dos_print.sha256`.
2. **Security.**
   - The pipe's DACL has exactly one ACE, an allow ACE for the current user's SID. The pipe rejects remote clients.
   - A `hello` with a wrong token returns `-32001` and the server closes the connection.
   - Any other method sent before `hello` returns `-32001` and closes the connection.
   - An agent connection calling an operator method returns `-32001` and stays open.
3. **Framing.** These close the connection without crashing the server:
   - a length prefix over 16 MiB;
   - a truncated message (the connection closes mid-message).

   Malformed JSON returns `-32700` and the connection stays open.
4. **Joystick.** After `set_joystick { x: 0 }` and then `{ x: 255 }`, BASIC's `PDL(0)` reads `0` and `255` respectively. Button 0 drives `PEEK(-16287) > 127`.
5. **Execution control.** In a realtime session:
   - `pause` returns, and then `EmulatedCycles` doesn't change for 500 ms of wall-clock time.
   - `resume` makes it advance again.
   - In a stepped session, `resume` returns `-32008`.
6. **Window closed.** In windowed mode, closing the window ends the process with exit code 0. The working copies are removed.

**Part B**
7. **Bell, headless.** After `subscribe_audio`, `PRINT CHR$(7)\n` produces a `sound_started` notification followed by `sound_stopped`. The `sound_stopped` reports a `duration_ms` between 50 and 200 and a `dominant_hz` within ±10% of the measured bell pitch, which the implementer records in the ledger.
   - `get_audio { from_cycle: start_cycle, duration_ms: 200 }` returns WAV data whose AC RMS is above -30 dBFS.
   - Audio from 30 s earlier returns `-32009`.
8. **Deterministic audio.** The same stepped script, run twice and once in each display mode, gives byte-identical `get_audio` data over the same cycle range. This moves part of M4's acceptance into M3.
9. **No AppleWin patches,** and nothing from M2 regresses:
   - the golden hash;
   - headless mode never loads `dsound.dll`;
   - windowed realtime mode plays sound, and the 60-second tone has 0 underruns;
   - the M2 `audio` suite still passes.

**Part C**
10. **Clock rates.** In realtime mode with sound off (headless), the measured emulated cycles per wall-clock second are within ±2% of `effective_clock_hz` for `machine_speed` 5, 10 and 20. Each measurement covers 3 s, after 1 s to settle.
11. **Full speed.** `machine_speed: "max"`, and also `full_speed_override: true` at speed 10, each run faster than 2× authentic speed.
12. **Clock multiplier.** For `clock_multiplier` values 0.3, 0.5, 0.75, 1.0, 1.55, 2.0, 3.95 and 10, the reported `machine_speed` equals what AppleWin's `UseClockMultiplier` produces for that input.
13. **Stepped mode ignores speed.** Running `step_frames 720` with `machine_speed` set to 5 and to 40 gives the same frame hash.

## D14 — Virtual sound buffers (new decision; recorded in `decisions.md` by Part B)
AppleWin never gets a real DirectSound buffer. The harness replaces the translation unit `external/AppleWin/source/Windows/DXSoundBuffer.cpp` in `AppleWinCore` with its own `src/host/virtual_sound.cpp`, the same way M1 replaced `AppleWin.cpp`. No AppleWin file is modified.
- **Symbols.** `virtual_sound.cpp` defines every symbol the rest of AppleWinCore uses from `DXSoundBuffer.cpp`: `DSInit`, `DSUninit`, `DSAvailable`, `GetDefaultAudioDeviceName`, `DXSoundBuffer::create` (which returns null and is never used), and any others the linker asks for.
  - `DSInit()` succeeds in every mode and opens no device.
  - `GetDefaultAudioDeviceName()` returns `"harness"`.
- **Virtual buffers.** `HarnessFrame::CreateSoundBuffer` returns a `VirtualSoundBuffer` in every mode. It is a memory ring of the requested size, rate and channels. Its cursors are derived so that AppleWin always sees the ideal fill:
  - the play cursor is the end of the last commit minus ⅜ of the buffer;
  - the write cursor is the end of the last commit (play cursor plus ⅜ of the buffer; ruling B6, so a voice that starts writing at the write cursor, like the Mockingboard, also sees the ideal fill from its first call);
  - nothing is ever dropped;
  - AppleWin's error correction stays at 0, so `g_nCpuCyclesFeedback` is always 0, and the Mockingboard's sample-count correction is too.
- **Determinism.** The samples AppleWin produces depend only on emulated time. This makes capture deterministic in every mode, and it removes the SSI263 timing difference between the display modes (final-review finding I2 of M2).
- **Capture.** Each commit to a virtual buffer, except a whole-buffer commit, appends its samples to `AudioCapture`. A whole-buffer commit is AppleWin re-initialising the buffer with zeros.
  - `AudioCapture` mixes all voices (speaker, Mockingboard, SSI263) into one 44,100 Hz stereo int16 timeline.
  - Mixing is additive with saturation. A voice at another rate is resampled linearly. A voice that commits more than 100 ms later than its *N* samples need (the gap exceeds *N* × CLK_6502_NTSC/rate cycles, rate being the voice's own sample rate, by over 0.1 × CLK_6502_NTSC) was paused: the gap is silence, and the commit is placed like a first commit.
  - Output sample *k* is emulated time `k / 44100` s since power-on.
  - The timeline is held in a ring buffer covering the last 30 s.
- **Playback.**
  - Only in windowed mode, and only during realtime runs, `AudioOutput` streams the mixed timeline to a harness-owned DirectSound buffer (delay-loaded `dsound.dll`).
  - The burst-size feedback that keeps that buffer between ¼ and ½ full replaces AppleWin's speaker feedback from D9. It uses the same rule and constants as `Spkr_SubmitWaveBuffer`: error increment and maximum from `SoundCore_GetErrorInc()` and `SoundCore_GetErrorMax()`, scaled to cycles per sample.
  - `AudioOutput` counts underruns of its own buffer. A counted underrun means the play cursor passed the end of the written data after playback started. This replaces `MonitoredSoundBuffer`, which is deleted, and `audio underruns` reports this count.
  - Outside realtime runs, `AudioOutput` writes silence.
- **Headless:** no `AudioOutput`, so no DirectSound is used.
- **Consequences:**
  - D9's statement that "windowed realtime burst sizes depend on the host audio device" now refers to the harness's own feedback.
  - D12's planned AppleWin patches are no longer needed.
  - D8's SSI263 exception is removed.

## Part A — server

### Launch
```
AppleWinHarness.exe --serve [--headless]
```
- **Usage error (exit 2):** `--serve` cannot be combined with `--realtime`, `--disk1`, `--png` or any step.
- **Announcement:** on start, the server prints exactly one line to stdout, then flushes:
  `{"pipe":"\\\\.\\pipe\\applewin-harness-<id>","agent_token":"<64 hex>","operator_token":"<64 hex>","pid":<n>}`
  - `<id>` is 32 random hex characters.
  - Tokens are 32 random bytes from `BCryptGenRandom`, written as hex. They are never written anywhere else.
  - Nothing else is written to stdout.
- **Shutdown:** the process exits after `close_session` has been answered, or when the window is closed (exit 0 in both cases). It also exits with 1 on a fatal error, after printing `error: …` to stderr.
- **Orphans:** the server also exits (0, with the normal cleanup) when the process that launched it exits. At startup it finds its parent pid and opens a `SYNCHRONIZE` handle; the main loop waits on that handle. If the parent is already gone or cannot be opened, it prints one line to stderr and runs without the watch.
- **Cleanup:** working copies and the INI are removed on every exit path.

### Transport (`src/server/pipe_server.{h,cpp}`)
- **Creating the pipe.** `CreateNamedPipeW` with:
  - `PIPE_ACCESS_DUPLEX | FILE_FLAG_OVERLAPPED`, plus `FILE_FLAG_FIRST_PIPE_INSTANCE` on the first instance;
  - `PIPE_TYPE_BYTE | PIPE_READMODE_BYTE | PIPE_WAIT | PIPE_REJECT_REMOTE_CLIENTS`;
  - at most 8 instances;
  - a security descriptor whose DACL has one allow ACE, `GENERIC_READ | GENERIC_WRITE`, for the current process token's user SID, and no other ACEs.
- **Hello deadline.** A connection that has not completed `hello` within 10 s of being accepted is closed.
- **Connections.** Each connection is served by its own thread using overlapped I/O, so reads and writes don't block each other.
- **Framing.** Each message is a 4-byte little-endian length followed by that many bytes of UTF-8 JSON.
  - A length of 0 or more than 16 MiB closes the connection.
  - Every outgoing message is written whole, under a per-connection mutex.
- **Handshake (D3).**
  - The first message must be `hello { protocol_version: "0.3", role: "agent" | "operator", token }`. A wrong token or role, or any other method first, gets error `-32001` and the connection closes.
  - A `protocol_version` other than `"0.3"` gets `-32600` and the connection closes.
  - The reply is `{ protocol_version: "0.3", role, display_mode }`.
  - The role is fixed for the connection's lifetime.
- **JSON.** nlohmann/json 3.11.3, vendored at `third_party/nlohmann/json.hpp` (MIT).
  - A body that isn't valid UTF-8 JSON gets `-32700`.
  - A message that isn't a JSON-RPC 2.0 request object gets `-32600`.
  - An unknown method gets `-32601`.
  - Bad params get `-32602`.
  - Notifications sent *by* clients are ignored.

### Threading and the session loop (`src/server/session.{h,cpp}`)
- **Main thread.** The emulator, the window and sound live on the main thread, as in M2. Connection threads parse and authorise requests, then post `Command { connection, id, method, params }` to a queue the main thread drains.
- **Replies.** Every reply and notification is sent from the main thread, through the connection's send function.
- **States:** `NoSession`, `Paused`, `Running` (Running exists only in realtime sessions).
  - **Running:** after each realtime step (M2's step primitive), the main thread drains the command queue and pumps the window.
  - **NoSession and Paused:** the main thread waits on `MsgWaitForMultipleObjects` (queue event plus window messages), with a 50 ms timeout, and handles whatever arrives.
- **Emulator API.** Commands are handled with the emulator's own API (`RunFrames` and so on). Long-running commands (`step_frames`) run to completion on the main thread before the reply is sent. Window messages are still pumped during them (M2 behaviour).

### Input queue (in `Emulator`; deterministic)
- **Where it lives.** `Emulator` gains an input queue that the step primitive processes after every step. M2's `TypeText` is reimplemented on top of it, with unchanged results: the M2 golden must still pass.
- **Events.** Each event has an earliest cycle. Each step boundary applies every event that is due, with these rules:
  - A key event also waits until the keyboard strobe is clear. Keys are first in, first out, so the next key waits for the previous one to be applied.
  - `type_text` key *i* is due at the later of the previous key's applied cycle plus `inter_key_delay_ms` (converted to cycles at the base clock) and the moment the strobe clears.
    - With `inter_key_delay_ms: 0` this is exactly M2's `TypeText` behaviour.
    - The default delay is 30.
  - `press_key { key, hold_ms = 50 }`:
    - **Key names:** one character from 0x20 to 0x7E; an int from 0 to 127; or `RETURN` (0x0D), `ESC` (0x1B), `TAB` (0x09), `DELETE` (0x7F), `LEFT`, `RIGHT`, `UP`, `DOWN` (sent through `KeybQueueKeypress(VK_…, NOT_ASCII)`), `CTRL-A`…`CTRL-Z` (0x01–0x1A), or `RESET`.
    - **Hold:** while the key is held, the //e any-key-down flag ($C010 bit 7) is set. The harness calls `KeybAnyKeyDown(WM_KEYDOWN, vk, false)`, then `WM_KEYUP` once `hold_ms` has elapsed, using the key's own VK where one exists and `VK_SPACE` otherwise.
    - **RESET** calls AppleWin's `CtrlReset()` and does not wait for the strobe.
  - `set_joystick { joystick = 0, x?, y?, buttons? { "0"?, "1"? }, duration_ms? }`:
    - Joystick 0 uses AppleWin's mouse-as-joystick seam. Start sets joystick type `J0C_MOUSE`, changing M2's `J0C_DISABLED`, so no host device is read. Values go through `JoySetPosition(x, 255, y, 255)` and `JoySetButton`.
    - Fields left out keep their values. Positions start at 127. `duration_ms` queues a restore of the previous state.
    - `joystick: 1` and button `"2"` return `-32006`.
    - Ruling for the implementer: if `J0C_MOUSE` changes any M2 golden, stop and report.
- **Input replies.** Each input method replies straight away with `{ input_id, applied_at_cycle }`.
  - `applied_at_cycle` is the cycle at which the input will take effect, when that's already known: the queue is empty ahead of it and, for a key, the strobe is clear. In that case it equals the current `EmulatedCycles()`, because input takes effect at the start of the next step (D10). Otherwise it is `null`.
  - When an input has fully taken effect, its connection receives the notification `input_applied { input_id, first_cycle, last_cycle }`. For `type_text`, that is the first and last key; for a hold or `duration_ms`, it is the press and the release.
- **Text.** `type_text` text may only contain 0x20–0x7E and `\n`, which becomes RETURN, and is at most 4,096 characters. Otherwise the error is `-32602`.

### Agent methods
- **`get_frame { format = "PNG" | "BGRA32", borders = false }`** returns `{ frame_id, emulated_cycles, width, height, stride, format, data }`.
  - `data` is base64 (`src/core/base64.{h,cpp}`, RFC 4648 with padding).
  - BGRA32 is returned top row first, with `stride = width × 4`.
  - The frame is `Emulator::Frame` (the last presented frame), and `frame_id` is `PresentedFrames()`.
- **`subscribe_frames { every_n_frames = 1 }`**, with `every_n_frames` from 1 to 600, sends `frame_ready { frame_id, emulated_cycles, width, height }` to that connection after every *n*-th presented frame. Calling it again replaces the setting. `every_n_frames: 0` unsubscribes.
- **Input:** `type_text`, `press_key`, `set_joystick`, as above.
- **Before a session exists,** every agent method returns `-32002`.

### Operator methods
- **`create_session { disks?: [{ slot: 6, drive: 1|2, path }], run_mode = "realtime" | "stepped", model = "apple2ee", speed?: {...}, allow_text_screen = false, shared_memory_frames = false }`** returns `{ session_id: <id> }`.
  - `path` must be absolute; otherwise `-32602`. A missing file returns `-32005`.
  - Each image gets a `WorkingCopy` in `%TEMP%\applewin-harness\<pid>\`.
  - Starts the emulator: windowed or headless per `--headless`, with drive 1 as `disk1`. Drive 2 is inserted after Start.
  - A realtime session starts Running; a stepped session starts Paused.
  - A second `create_session` returns `-32008`.
  - `speed` is handled in Part C. Until then, any `speed` field returns `-32006`.
- **`close_session {}`** replies `{}`, then shuts down and exits (exit code 0).
- **`pause {}`** — in realtime mode it runs until the next present, then pauses, and replies `{ emulated_cycles }`. If already paused, it replies immediately.
- **`resume {}`** — realtime only, otherwise `-32008`. Replies `{}`.
- **`step_frames { frames: 1..100000 }`** pauses first if the session is running. It then runs `RunFrames(frames, Stepped)` and replies `{ emulated_cycles }`. If the window was closed during the step, it replies `-32008`, and the process exits once the reply is sent.

### Errors
As in `api_spec.md`. `-32603` carries the C++ exception's `what()` in `message`.

## Part B — agent audio
- **`get_audio { from_cycle?, duration_ms = 1000, format = "WAV" | "PCM16" }`**
  - `duration_ms` must be 1 to 30,000; otherwise `-32602`.
  - Without `from_cycle`, the range is the most recent `duration_ms`.
  - Returns `{ start_cycle, end_cycle, sample_rate: 44100, channels: 2, format, data }`. `data` is base64 of a canonical 44-byte-header WAV, or of raw little-endian int16 interleaved samples.
  - A range that starts before the oldest buffered sample returns `-32009`.
  - A range extending past the newest sample is cut short. `end_cycle` reports the actual end.
- **`subscribe_audio { threshold_db = -50, min_silence_ms = 100 }`** sends `sound_started { start_cycle, emulated_ms }` and `sound_stopped { start_cycle, end_cycle, duration_ms, peak_db, dominant_hz }`. `threshold_db` must be a number in -120..0 and `min_silence_ms` an integer in 10..10000; otherwise `-32602`. Events are produced 110 ms behind the newest committed audio (a voice can commit up to ~64 ms after another), so a trailing sound's `sound_stopped` arrives once emulation has advanced that far.
  - **Level:** the AC RMS in dBFS of each 10 ms block, measured after subtracting the block's mean. Subtracting the mean removes the speaker's DC level; the block's least-squares linear trend is removed too, because AppleWin's speaker ramps its DC level back to zero (one unit per sample) after a sound, and that ramp is not sound.
  - **Start and stop:** sound starts at the first block above the threshold. It stops after `min_silence_ms` of consecutive blocks below it; `end_cycle` is the end of the last block that was loud.
  - **`dominant_hz`:** the peak bin of a Hann-windowed FFT over the first 16,384 samples of the sound (mono mix), refined by parabolic interpolation. If the sound is shorter than that, the FFT covers the sound zero-padded.
- **Mute.** Agent audio is never muted. Capture runs whenever the emulator runs.

## Part C — speed (D11)
- **Methods.** `set_speed` and `get_speed` are exactly as in `api_spec.md`. `create_session.speed` takes the same fields, except `video_refresh`, which accepts only 60 for now.
- **AppleWin calls.**
  - `machine_speed` sets `g_dwSpeed` and then calls `SetCurrentCLK6502()`.
  - `clock_multiplier` calls `UseClockMultiplier(x)`, and `get_speed` reports the resulting `g_dwSpeed`. Sending it together with `machine_speed` returns `-32602`.
  - `enhance_disk_speed` calls `GetCardMgr().GetDisk2CardMgr().SetEnhanceDisk(b)`.
  - `full_speed_override` is a harness flag that stands in for Scroll Lock.
- **Realtime steps** use AppleWin's `ContinueExecution` full-speed conditions:
  ```
  g_bFullSpeed = g_dwSpeed == SPEED_MAX || override
              || (disk2 IsConditionForFullSpeed && !Spkr_IsActive() && !MockingboardCardMgr.IsActiveToPreventFullSpeed())
  ```
  - **At full speed:** steps run unpaced with `CpuExecute(cycles, false)`. On entering full speed the harness calls `VideoRedrawScreenDuringFullSpeed(0, true)`, then calls it again at most every 16 ms of wall-clock time, and calls `VideoRedrawScreenAfterFullSpeed` on leaving. Those are AppleWin's calls. `frame_ready` is limited to 60 per wall-clock second.
  - **Otherwise:** paced steps of `g_fCurrentCLK6502 × 1 ms` plus `AudioOutput` feedback.
- **Stepped mode** never enters full speed and always renders video (D9).
- **`get_speed` fields:**
  - `full_speed_reasons` lists `"machine_speed_max"`, `"override"` and `"disk_motor"` in that order.
  - `effective_clock_hz` is `g_fCurrentCLK6502`, or `null` when `machine_speed` is 40.
  - `base_clock_hz` is `CLK_6502_NTSC`.
