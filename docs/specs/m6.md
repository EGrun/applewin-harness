# M6 Spec — Hardening and release

**Status:** Draft. **Milestone:** M6 in `project.md`. **Decisions:** D6 (decided here), D10. **Builds on:** `docs/specs/m5.md`. **API reference:** `docs/api_spec.md`. This spec overrides `api_spec.md` where the two differ; the docs task updates it.

## Goal
The harness is safe to leave running against an untrusted or buggy client, it reports what it is doing in a form a machine can read, and it ships as a portable, correctly licensed zip that CI builds and tests end to end.

## Non-goals
- Multiple sessions per process, remote transports, record/replay and batch orchestration ("Later" in `project.md`).
- Split-independent audio capture (ruling B13 stands) and PAL (`video_refresh: 50`). Both stay parked.
- An installer, code signing or auto-update. The release is a zip.
- Shipping disk images. The bundle contains none, and the repository adds none: tests keep using the images in the AppleWin submodule.

## Pass conditions
1. **Input limits.** Every limit below is enforced with the stated error, and values at the limit are accepted. (Pipe tests.)
2. **Queue limit.** A client that queues inputs faster than they are applied gets `-32010` once the queue is full. The session stays usable, and the queue drains normally afterwards. (Pipe test.)
3. **Request size.** An oversized request closes only that connection, logs one warning, and leaves other connections and the session working. (Pipe test.)
4. **Structured logging.**
   - With `--log-format json`, every line the harness writes to stderr is one JSON object with the fields below.
   - Operator connections receive `log` notifications for warnings and errors.
   - The adapter logs in the same two formats.

   (Pipe and adapter tests.)
5. **`disk_written`.** A `SAVE` to drive 1 sends one `disk_written {slot: 6, drive: 1}` notification to operator connections that subscribed to it. (Pipe test.)
6. **Non-ASCII work path (D10 mitigation).** With `%TEMP%` pointing at a directory whose name has non-ASCII characters and an 8.3 short name, `checkpoint` and `restore_checkpoint` succeed. Without a short name they still fail with `-32004`, as today. (Pipe test; skipped when the volume has 8.3 names disabled, and it says so.)
7. **Release bundle.**
   - `tools/make_release.ps1` builds `dist/applewin-harness-<version>-win64.zip` from a Release build.
   - The bundle has the layout below and no disk images.
   - Extracted to a fresh directory, the bundled exe and adapter pass the M5 end-to-end adapter test (pass condition 1 of M5), using only what is in the zip plus `pip install -r adapter/requirements.txt`.

   This runs in CI, and the zip is uploaded as an artifact.
8. **Licensing (D6).** The repository and the bundle carry the license files below, every source file the harness owns has an SPDX header, and the bundle's `THIRD-PARTY-NOTICES.txt` covers everything linked into the exe. (A test checks that the headers and files are present.)

## Input and request limits (harness)
| What | Limit | Error |
|---|---|---|
| `press_key.hold_ms` | 0–10,000 | `-32602` |
| `set_joystick.duration_ms` | 0–60,000 | `-32602` |
| `type_text.inter_key_delay_ms` | 0–1,000 | `-32602` |
| `type_text.text` | 4,096 characters (unchanged) | `-32602` |
| Pending input events in the session | 4,096 | `-32010` |
| Request message size | 1 MiB | the connection is closed |
| Any string parameter | 32,767 UTF-16 code units | `-32602` |

- **Counting the queue.** A key counts as one event, as does a joystick change (its timed release counts as a second one). A `type_text` of *n* characters counts as *n*. The check is all or nothing: a request that would take the queue past 4,096 is rejected whole, and nothing from it is queued. `restore_checkpoint` empties the queue, as it already does.
- **`-32010` "Input queue full."** This is a new error code, added to the table in `api_spec.md`. Its `data` is `{ pending, limit }`.
- **Request size.** Replies and notifications keep the 16 MiB frame limit, because `get_frame` BGRA32 needs it. A length prefix over 1 MiB on an incoming request closes the connection before the body is read, and logs a `warning`.
- **The planned "200 events per emulated second" is dropped.** Ruling: in stepped mode, a client queues while emulated time stands still, so a rate per emulated second would reject ordinary scripts. The queue-depth cap plus the per-value caps bound both memory and how far ahead a client can schedule.
- **The adapter's own caps** (`wait` 1–60,000, `listen` 0–60,000) are unchanged. The adapter passes the harness limits through: a `press_key` with `hold_ms` over 10,000 is a tool error carrying the harness message.

## Structured logging
- **Harness flag:** `--log-format text|json`, default `text`. Text is today's `level: message` format.
- **JSON lines on stderr:** `{ "ts": "<UTC ISO-8601 with ms>", "level": "debug"|"info"|"warning"|"error", "msg": "...", "component": "main"|"server"|"session"|"emulator"|"audio", ...extra }`. One object per line, with nothing else on stderr. AppleWin's own `LogOutput` / `LogFileOutput` stays off, as today.
- **Routing:** every existing `std::cerr` / `fprintf(stderr)` line goes through one logger (`src/host/log.{h,cpp}`). The usage text for a command-line error is the one exception: it stays plain text, because it is printed before the format is known to be valid.
- **Operator `log` notification:** `{ level, message, emulated_ms }`, already in `api_spec.md` and now implemented. Every `warning` and `error` goes to all operator connections; `info` and `debug` don't. It is always on; there is no subscribe call.
- **Adapter:** `--log-format text|json`, using Python's `logging` with a JSON formatter of the same shape (`component: "adapter"`). It passes the same flag to the harness it launches. stdout is still MCP only.
- **What gets logged at info:** startup (version, pipe name, display mode), session create/close, checkpoint/restore, disk insert/eject/export, connection open/close (role, not token), and limit rejections at `warning`. Tokens, and the text a client types, are never logged.

## `disk_written` (operator notification)
- **Subscription:** `subscribe_disk_writes {}` / `unsubscribe_disk_writes {}` on an operator connection.
- **When it fires:** `disk_written { slot: 6, drive }` is sent once per write burst. A burst ends when the drive has gone 1 emulated second without a write, or at the next `checkpoint`, `export_disk`, `eject_disk` or `close_session`, whichever comes first.
- **Purpose:** it tells an operator that `export_disk` now has something new.

## D10 mitigation: 8.3 short paths
- The harness inserts each working copy into AppleWin through `GetShortPathNameW`. It uses the short path when the long path's UTF-8 and ANSI bytes differ and the short path is pure ASCII.
- `list_disks.working_path` keeps reporting the long path.
- `checkpoint` refuses (`-32004`, as today) only when no ASCII path exists.

## Licensing (D6, decided 2026-10-18 by the user)
- **MIT where possible.** Everything the harness project wrote is MIT: `src/`, `tests/`, `adapter/`, `tools/` and `docs/`. A root `LICENSE` holds the MIT text, and each owned source file gets an `SPDX-License-Identifier: MIT` header.
- **GPL where required.** `AppleWinHarness.exe` and `HarnessTests.exe` link AppleWin (GPL-2.0-or-later), so those binaries, as combined works, are distributed under **GPL-2.0-or-later**.
  - `LICENSE-GPL-2.0.txt` holds the GPL text, copied from the submodule.
  - The README's "License" section says this plainly.
  - The bundle's `NOTICE.txt` gives the source offer: this repository's URL and tag, plus the pinned AppleWin commit (D7).
- **Third-party notices:** `THIRD-PARTY-NOTICES.txt` lists everything linked into the exe, each with its license text:
  - AppleWin (GPL-2.0-or-later);
  - zlib (zlib);
  - minizip (zlib);
  - libyaml (MIT);
  - nlohmann/json (MIT).

  It also lists the adapter's runtime dependency `mcp` (MIT), which is installed by pip and not bundled. doctest (MIT) is only in the test binary, so the bundle doesn't include it.
- **ROM images:** AppleWin compiles Apple II ROM images into the exe as resources, and so does the harness. The bundle includes them on the same terms AppleWin's own releases do. `NOTICE.txt` says so. *Recorded as a risk in `project.md`.*
- **Disk images:** none in the repository or the bundle. The README says where to get the DOS 3.3 System Master: the AppleWin repository's `bin/` directory.

## Release bundle
- **Version:** a root `VERSION` file holds `0.1.0`. It is the single source for the zip name, the startup log line, the `hello` reply's existing `server_version` field (check it exists, and add it if it doesn't), and the adapter's `__version__`.
- **`tools/make_release.ps1 [-Configuration Release] [-OutDir dist]`:**
  - It builds nothing itself; it fails clearly if `bin\x64\Release\AppleWinHarness.exe` is missing.
  - It checks that the exe was built from the current HEAD (the exe's version resource or the build stamp matches `VERSION`), and warns if the working tree is dirty.
- **Zip layout:**
  ```text
  applewin-harness-<version>-win64/
    AppleWinHarness.exe
    adapter/applewin_mcp/*.py
    adapter/requirements.txt
    adapter/README.md
    adapter/examples/basic_count.md
    docs/api_spec.md
    README.md
    LICENSE
    LICENSE-GPL-2.0.txt
    NOTICE.txt
    THIRD-PARTY-NOTICES.txt
  ```
  It contains no `.pdb`, `.lib`, test binaries or disk images.
- **Example config paths:** in a bundle, `adapter/examples/basic_count.md` refers to `<BUNDLE>\AppleWinHarness.exe`. The script rewrites the `<REPO>\bin\x64\Release\` paths, and a test checks the result.
- **CI:** in the Release job, after the existing tests:
  1. run `make_release.ps1`;
  2. extract the zip to `$RUNNER_TEMP`;
  3. run the M5 end-to-end adapter test against the extracted exe and adapter, with `HARNESS_EXE` and `PYTHONPATH` pointing into the extraction;
  4. upload the zip with `actions/upload-artifact`.

## Tests and CI
- **Pipe tests** (`tests/python/test_limits.py` and `test_logging.py`): pass conditions 1–6.
- **Adapter tests:**
  - a JSON log line format check;
  - the harness limit errors coming back as tool errors;
  - a bundle smoke test, which is the M5 end-to-end test run from the extracted bundle when `HARNESS_BUNDLE_DIR` is set, and skipped otherwise.
- **Licensing test** (`tests/python/test_licensing.py`):
  - SPDX headers are present on owned `.cpp`, `.h` and `.py` files;
  - the license files exist;
  - the bundle (when built) contains exactly the expected layout;
  - the bundle has no `.dsk`, `.do`, `.po`, `.nib` or `.woz` files.
- The C++ suite and the M1/M2 goldens still pass, and no AppleWin source is modified.
