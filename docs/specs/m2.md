# M2 Spec — Vertical slice: window, sound, keyboard, disks

**Status:** Implemented. **Milestone:** M2 in `project.md`. **Decisions:** D5, D7, D8, D9, D10, D13 in `decisions.md`. **Builds on:** `docs/specs/m1.md`.

## Goal
The harness boots DOS 3.3 from a working copy of a disk image, types into the Apple with the emulated keyboard, and captures the screen. It runs windowed with sound by default, so a person can watch and listen, or headless with `--headless`. A scripted run gives the same frame checksum in both modes. CI builds the harness and runs the headless tests on a Windows runner.

## Non-goals (later milestones)
- The JSON-RPC server, joystick input and speed controls (M3).
- Agent audio capture (M3, D12). M2 only plays sound.
- AppleWin's full-speed conditions (enhanced disk speed, Scroll Lock, `SPEED_MAX`). M2 always runs at authentic speed in realtime mode. D11 adds them in M3.
- Checkpoints and the original-image hash check across sessions (M4).
- Typing into the window. The window is view-only (D8).

## Pass conditions
1. **DOS 3.3 golden, headless.** `AppleWinHarness.exe --headless --disk1 "<DOS 3.3 System Master>" --frames 720 --type "PRINT 2+2\r" --frames 60 --png <path>` exits with 0. It prints exactly `sha256 <hash>`, and the hash equals `tests/golden/m2_dos_print.sha256`. A person has looked at the PNG and confirmed it shows `]PRINT 2+2`, then `4`, then a blank line (DOS 3.3 prints it), then `]`.
2. **Same golden, windowed.** The same command without `--headless` prints the same hash. It may also print an `audio underruns` line (see the command line section).
3. **In-process.** Text page 1 contains the four consecutive rows `]PRINT 2+2`, `4`, an empty row, and `]` after the same script run through the `Emulator` API.
4. **Working copy.** The original image file is never opened for writing. Its SHA-256 and last-write time are unchanged after a run. The working copy is gone after the process exits.
5. **No options.** Running `AppleWinHarness.exe` with no options opens a visible window showing the live Apple screen and plays sound. Closing the window exits with 0.
6. **View-only.** Keys and mouse clicks sent to the window during a run don't change the result. The frame hash equals the hash of the same run without them.
7. **Bell.** In windowed realtime mode, `PRINT CHR$(7)` plays the bell. *Human check.*
8. **No underruns.** A 60-second speaker tone at authentic speed in windowed realtime mode reports `audio underruns 0`.
9. **Headless is silent.** In headless mode, `dsound.dll` is never loaded, AppleWin's `DSAvailable()` is false, and no sound buffer is created.
10. **CI.** A GitHub Actions workflow on `windows-2022` checks out submodules recursively (D7), builds Debug and Release x64, and runs `HarnessTests.exe -tse=windowed,audio`, which includes pass condition 1. Both configurations pass.
11. All M1 pass conditions still hold, including the M1 golden boot hash and the empty AppleWin patch list.

## Build changes
- **Shared property sheet** `build/Harness.props`: holds the include directories, preprocessor definitions, system libraries and linker options that `HarnessCore`, `AppleWinHarness` and `HarnessTests` currently repeat. All three import it. `AppleWinCore` keeps AppleWin's own settings.
- **Delay-loaded DirectSound:** both exes link with `/DELAYLOAD:dsound.dll` and `delayimp.lib`, so headless runs never load `dsound.dll` (pass condition 9).
- `emulator.h` includes no AppleWin header. `EmulatorConfig::model` is removed; the model is always Apple //e Enhanced (`A2TYPE_APPLE2EENHANCED`) until a later milestone needs others.

## Harness modules (namespace `harness`)

### `src/host/harness_frame.h` — rename of `HeadlessFrame`
`HeadlessFrame` becomes `HarnessFrame`, because it now serves both display modes (D8). Its files are renamed to `harness_frame.{h,cpp}` and its tests to `tests/harness_frame_test.cpp`, with the test-name prefix `frame:`. Behaviour is unchanged except for the following.
- **Presented frame.** `VideoPresentScreen()` copies the whole video buffer (with borders) into a snapshot before calling the present hook. `FrameView PresentedFrame(bool borders) const` returns a view of that snapshot, laid out like the live buffer (bottom-up BGRA32, negative stride). Before the first present, the snapshot is all zero.
- **Present hook.** `void SetPresentHook(std::function<void()>)`. It is called after each snapshot. An empty hook does nothing.
- **Sound.** `void EnableSound(bool)`, default false.
  - When sound is off, `CreateSoundBuffer` returns `nullptr` (AppleWin's no-sound path), as in M1.
  - When sound is on, it returns a `MonitoredSoundBuffer` wrapping `DXSoundBuffer::create(...)`, or `nullptr` if that returns `nullptr`.
  - `void SetSoundMuted(bool)` mutes or unmutes every buffer created so far, and applies to buffers created later.
  - `uint64_t SoundUnderruns() const` is the sum over all buffers. `size_t SoundBuffersCreated() const` counts non-null buffers returned.

### `src/host/monitored_sound_buffer.h`
`class MonitoredSoundBuffer final : public SoundBuffer` wraps another `SoundBuffer` of a known size in bytes. Constructor: `MonitoredSoundBuffer(std::shared_ptr<SoundBuffer> inner, uint32_t bufferBytes)`. It forwards every call to `inner`, except as follows.
- **Muting.**
  - `SetMuted(true)` sets the inner volume to `DSBVOLUME_MIN`.
  - While muted, `SetVolume(v)` only records `v`, and `GetVolume` returns the recorded value.
  - `SetMuted(false)` restores the recorded volume. The recorded volume starts as the inner buffer's volume when the wrapper is constructed.
  - Buffers start unmuted.
- **Underruns.** The wrapper tracks the end of the last committed write: the offset passed to `Lock` plus the bytes passed to the matching `Unlock`, modulo `bufferBytes`.
  - When `GetCurrentPosition` succeeds while tracking, it counts one underrun if that end offset lies in the unsafe zone between the play and write cursors. The zone uses the same predicate as `SoundCore_ValidateAndAlignWriteOffset` in `SoundCore.cpp`. After an underrun, tracking stops until the next commit.
  - Tracking is off at construction, while muted, after unmuting, and after a commit that covers the whole buffer (AppleWin's `DSZeroVoiceWritableBuffer` re-initialisation). Each of these waits for the next partial commit before tracking resumes.
  - **Armed only once playback has begun (ruling R11).** The wrapper records the play cursor returned by the first successful `GetCurrentPosition`. Until a later successful `GetCurrentPosition` returns a different play cursor, no underrun is counted, and such calls leave tracking unchanged. From the call that sees the cursor move (that call included), counting follows the rules above. Once armed, the wrapper stays armed for the buffer's life; muting doesn't disarm it. Reason: DirectSound holds the cursors still after `Play()` until the device starts the buffer, and AppleWin's lazily created voices (the Mockingboard's) write at the write cursor during that window, so the predicate would report underruns on audio that has not started playing.
  - `uint64_t Underruns() const`.

### `src/host/window.h` — the view-only presenter
`class Window` owns one top-level Win32 window on the calling thread.
- **Construction.** `explicit Window(const std::wstring& title)` registers the class `AppleWinHarnessWindow` once per process. It creates a `WS_OVERLAPPEDWINDOW` with a client area of 1120×768 (the borderless frame at 2×), shows it, and throws `std::runtime_error` on failure.
- **Display.**
  - `void Show(const FrameView&)` copies the frame into a top-down BGRA buffer and invalidates the client area.
  - `WM_PAINT` draws that buffer scaled to the client area with `StretchDIBits` (`COLORONCOLOR`).
  - `const std::vector<uint8_t>& Pixels() const` returns the copied buffer, `width*height*4` bytes, top row first.
- **Messages.** `bool Pump()` dispatches every pending message for the thread with `PeekMessage`, and returns `!Closed()`.
- **Closing.** `WM_CLOSE` destroys the window. `bool Closed() const` is then true. The destructor destroys the window if it's still open.
- **Access.** `HWND Handle() const`.
- **View-only (D8).** Keyboard and mouse messages go to `DefWindowProc` only. Nothing in `Window` calls AppleWin.

### `src/core/working_copy.h`
`class WorkingCopy` makes the copy that D5 requires.
- **Construction.** `WorkingCopy(const std::filesystem::path& original, const std::filesystem::path& workDir)` creates `workDir` if needed and copies `original` to `workDir / original.filename()`. It clears the read-only attribute on the copy.
- **Errors.** Throws `std::runtime_error` naming the file if `original` doesn't exist, isn't a regular file, or can't be copied.
- **Copy.** `const std::filesystem::path& Path() const` returns the copy's path.
- **Cleanup.** The destructor deletes the copy, and also deletes `workDir` if it is then empty. It never throws.
- **Ownership.** Move-only.
- The original is only ever opened for reading.

### `src/host/emulator.h` — changes
```cpp
enum class DisplayMode { Windowed, Headless };
enum class Pacing { Stepped, Realtime };

struct EmulatorConfig {
    std::filesystem::path configIni;              // absolute; AppleWin settings file (g_sConfigFile)
    DisplayMode display = DisplayMode::Windowed;  // D8 default
    std::filesystem::path disk1;                  // optional; image to insert in slot 6 drive 1 before boot
};
```

New or changed members:
- `void Start(const EmulatorConfig&)`
  - **Windowed:** creates the `Window` (title `AppleWin Harness (view only)`) and sets `GetFrame().g_hFrameWindow` to its handle. Calls `DSInit()`.
    - If `DSInit()` succeeds: `g_bDisableDirectSound = false`, `EnableSound(true)`, sound muted.
    - If it fails: prints `warning: no audio device; running without sound` to stderr and continues as if headless for sound.
    - The present hook shows each presented frame in the window and pumps its messages.
  - **Headless:** exactly the M1 sound setup: `g_bDisableDirectSound = true`, no `DSInit()`, no window.
  - **Both modes:** joysticks 0 and 1 are set to `J0C_DISABLED` / `J1C_DISABLED` before `JoyInitialize()`, so no host joystick is ever read. If `disk1` is set, it is inserted (writable) in slot 6 drive 1 before boot. An insert error is a startup failure: the `FrameMessageBox` text goes into the exception, as in M1.
- `void Shutdown()` — releases every sound voice (speaker and Mockingboard) before `DSUninit()`, then destroys the window. Debug builds must not hit an `_ASSERT`. Safe to call twice.
- `void PowerCycle()` — as M1. It also makes `EmulatedCycles()` count from 0 again.
- `uint64_t EmulatedCycles() const` — cycles since the last power-on (D10). That is `g_nCumulativeCycles` minus its value at the last `Start` or `PowerCycle`.
- `bool RunFrames(uint32_t frames, Pacing pacing = Pacing::Stepped)`
  - Runs until `EmulatedCycles()` has grown by exactly `frames × NTSC_GetCyclesPerFrame()`, or by more only because of the last instruction.
  - It runs in steps of 1 ms or less, as M1 does.
  - **`Realtime`:** each step is `BurstBudget::Next() + g_nCpuCyclesFeedback`, clamped to ≥ 0 and to the cycles remaining, followed by `RealtimePacer::WaitForTick()` (D9). In headless mode the feedback stays 0.
  - **Sound:** unmuted only during a `Realtime` run, and muted again before returning.
  - **Window closed:** returns false if the window was closed (checked after every step), true otherwise.
- `bool RunRealtime(std::chrono::milliseconds)` — as M1, plus the speaker feedback, the unmute rule and the window-closed rule above.
- `bool TypeText(std::string_view text, Pacing pacing = Pacing::Stepped)`
  - Throws `std::invalid_argument` before typing anything if a byte is not `0x0D` or `0x20`–`0x7E`.
  - For each byte, it runs (as `RunFrames` does, by step) until the keyboard strobe is clear (`KeybReadData() & 0x80` is 0), then calls `KeybQueueKeypress(byte, ASCII)`.
  - It returns right after queueing the last byte.
  - If the strobe stays set for 600 frames of emulated time, it throws `std::runtime_error("TypeText: keyboard not read")`.
  - Returns false if the window was closed.
- `void InsertDisk(int drive, const std::filesystem::path&)` and `void EjectDisk(int drive)` — slot 6, drive 0 or 1, otherwise `std::out_of_range`. An insert error throws `std::runtime_error` with AppleWin's message. These take effect on the next boot or when DOS next reads the drive. Tests use them, together with `PowerCycle`, to boot DOS in the shared emulator.
- `FrameView Frame(bool borders = false) const` — **changed:** returns the last presented frame (`HarnessFrame::PresentedFrame`), not the live scanning buffer. Hashes are then always taken from a complete frame.
- `uint64_t SoundUnderruns() const` and `bool SoundActive() const` (true when windowed and `DSInit()` succeeded).

### `src/main.cpp` — command line
```
AppleWinHarness.exe [--headless] [--realtime] [--disk1 <image>] [--png <path>] [step ...]
step: --frames <n> | --type <text>
```
- **Startup.** Starts the emulator with the INI at `%TEMP%\applewin-harness\<pid>.ini`, as M1 does. If `--disk1` is given, it first makes a `WorkingCopy` of the image in `%TEMP%\applewin-harness\<pid>\` and boots from the copy.
- **Steps.** Steps run in command-line order. `--frames n` calls `RunFrames(n)`. `--type text` calls `TypeText(text)`. Both use `Pacing::Realtime` when `--realtime` is given, and `Pacing::Stepped` otherwise.
- **`--type` escapes.** `\r` and `\n` both mean Return (0x0D), and `\\` means a backslash. Any other backslash sequence, an empty text, or a character outside `0x20`–`0x7E` is a usage error.
- **`--frames` value.** 1–9 decimal digits, as M1's `--boot-frames`. `--boot-frames` is removed.
- **After the last step:**
  - Writes the PNG if `--png` was given.
  - Prints `sha256 <FrameHash(Frame())>` on stdout.
  - If `SoundActive()`, also prints `audio underruns <n>` on stdout.
  - Exits. The window closes with the process.
- **No steps:**
  - Windowed: runs `RunRealtime` in a loop until the window is closed, then exits with 0. It prints nothing on stdout.
  - Headless: a usage error.
- **Window closed during the steps:** prints `error: window closed` to stderr and exits with 1.
- **Output in headless mode:** stdout is exactly the hash line and stderr stays empty on success, as in M1.
- **`--disk1`, `--png`, `--headless` and `--realtime`** may each appear once.
- **Exit codes:** `0` success, `2` bad arguments (usage on stderr), `1` any other failure, including unknown exceptions (`catch (...)`).
- **Cleanup on every exit path:** the INI and the working copy are removed.

## Test layout
- **New CLI tests** in `tests/cli_test.cpp`:
  - **The DOS image** is found at `<repo>/external/AppleWin/bin/DOS 3.3 System Master - 680-0210-A.dsk`.
  - **M1's tests** change from `--boot-frames 120` to `--headless --frames 120`. "No arguments exits 2" becomes "headless with no steps exits 2".
  - **Doctest test suite `windowed`:** CLI tests that need a desktop session (pass conditions 2, 5 and 6). They find the harness window by its class name and the child's process id.
  - **Doctest test suite `audio`:** tests that need an audio device. Pass condition 8 is the realtime speaker-tone run, about 70 s. It boots DOS, types `10 X=PEEK(-16336):GOTO 10\rRUN\r`, then runs 3,600 realtime frames. If the harness prints the no-audio-device warning, the test is skipped with a message.
- **Golden:** `tests/golden/m2_dos_print.sha256`. It is recorded from the first passing run and marked provisional in the ledger until a person approves the PNG (pass condition 1).
- **CI:** `.github/workflows/ci.yml`, as in pass condition 10.
- **Unchanged:** the shared emulator fixture stays headless. The `realtime` suite from M1 stays.
