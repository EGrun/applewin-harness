# M1 Spec — Host the AppleWin core headless

**Status:** Implemented. **Milestone:** M1 in `project.md`. **Decisions:** D2, D7, D9, D10 in `decisions.md`.

## Goal
The harness links AppleWin's emulation core in-process, boots an Apple //e Enhanced with no window and no sound, and can run it two ways: as fast as possible (frame-exact) or paced to real time. It can save the screen as a PNG. This milestone tests whether D2 (hosting the core) is workable.

## Non-goals (later milestones)
- The window and sound playback (M2).
- Disks, keyboard and joystick input (M2).
- The JSON-RPC server (M3).
- Speed controls (M3).
- Agent audio (M3).
- Checkpoints (M4).
- AppleWin's speaker feedback, which only matters with sound (D9).

## Pass conditions
1. `AppleWinHarness.exe --boot-frames 120 --png <path>` exits with code 0. It writes a PNG of the 560×384 boot screen and prints `sha256 <64 hex chars>` to stdout. A person has looked at the PNG and confirmed it shows the //e boot screen the right way up. Its hash is stored as the reference ("golden") hash.
2. After a power-on and 120 frames, row 0 of text page 1 contains `Apple //e`.
3. Two power-on-plus-120-frame runs in the same process produce identical frame hashes, and both match the golden hash.
4. Running for 2,000 ms of wall-clock time in realtime mode advances the emulator by 2 × 1,020,484 cycles, ±2%.
5. Running the emulator never writes to the registry key `HKCU\Software\AppleWin`. All configuration goes to an INI file the harness chooses.
6. **The AppleWin patch list is empty.** No file under `external/AppleWin` is modified. If a patch turns out to be unavoidable, stop and report it, because it feeds the D2 decision.

- **Resources:** both exes compile `Applewin.rc`, so the ROMs are embedded the same way they are in AppleWin.

The system libraries are the x64 `AdditionalDependencies` from AppleWin's project: `iphlpapi htmlhelp comctl32 winmm dsound dxguid version strmiids dinput8 user32 gdi32 advapi32 shell32 comdlg32 ole32 wsock32 shlwapi`, plus `ddraw.lib` (AppleWin's video code references DirectDraw symbols).
- **Platform:** x64, Debug and Release only.

## Harness modules (namespace `harness`)

### `src/core/frame_view.h`
```cpp
struct FrameView {
    const uint8_t* topRow;   // first byte of the top visible row
    uint32_t width, height;  // pixels
    int32_t strideBytes;     // distance from one row to the next row down; negative for bottom-up buffers
};                           // pixels are BGRA32 (AppleWin bgra_t); alpha is ignored
std::vector<uint8_t> ToRgbTopDown(const FrameView&);   // width*height*3 bytes
```

### `src/core/png_writer.h` — uses zlib from the submodule
- `std::vector<uint8_t> EncodePng(const FrameView&);`
  - Produces an 8-bit RGB PNG (colour type 2, no interlace).
  - Writes one IDAT chunk. Every row uses filter type 0.
  - Chunk CRCs are computed with zlib's `crc32`.
  - Throws `std::invalid_argument` if width or height is 0, or `topRow` is null.
- `bool WritePngFile(const std::filesystem::path&, const FrameView&);`
  - Returns false if the file can't be written.

### `src/core/sha256.h` — uses Windows BCrypt
- `std::string Sha256Hex(std::span<const uint8_t>);` returns 64 lowercase hex characters.
- `std::string FrameHash(const FrameView&);` is defined as `Sha256Hex(ToRgbTopDown(view))`.

### `src/core/pacing.h`
- `class BurstBudget { public: BurstBudget(double clockHz, std::chrono::microseconds period); uint32_t Next(); };`
  - Hands out a cycle count for each burst.
  - Carries the fractional remainder forward, so N bursts add up to exactly `floor(N × clockHz × period)`.
  - Throws `std::invalid_argument` if `clockHz <= 0` or the period is ≤ 0.
- `class RealtimePacer { public: RealtimePacer(); ~RealtimePacer(); void Start(); void WaitForTick(); };`
  - Creates a one-shot high-resolution timer with `CreateWaitableTimerExW(..., CREATE_WAITABLE_TIMER_HIGH_RESOLUTION, TIMER_ALL_ACCESS)`. It is not periodic: each tick re-arms the timer to an absolute deadline (start + N × 1 ms), so timing error doesn't accumulate.
  - If the caller stalls, the pacer makes up the lost ticks when the stall is 50 ms or less, and drops the backlog (resyncs the deadline to now) when it is longer.
  - Throws `std::runtime_error` if the timer can't be created.

### `src/host/headless_frame.h`
`class HeadlessFrame final : public FrameBase` implements every pure virtual in `FrameBase.h`:

| Method | Behaviour |
|---|---|
| `Initialize(reset)` | Allocates a zeroed buffer of `GetVideo().GetFrameBufferWidth() × Height() × 4` bytes and calls `GetVideo().Initialize(buffer, reset)`. |
| `Destroy()` | Calls `GetVideo().Destroy()` and frees the buffer. |
| `VideoPresentScreen()` | Increments `presentedFrames()`. |
| `FrameMessageBox(text, caption, type)` | Appends `"caption: text"` to `messages()`, writes it to stderr, and returns `IDOK`. **It must never show any UI.** |
| `GetResource(id, type, size)` | Same logic as `Win32Frame::GetResource`: look up the resource in the current exe and return null if it's missing or the wrong size. |
| `CreateSoundBuffer(...)`, `CreateNetworkBackend(...)` | Return `nullptr`. |
| `GetBitmap(id, cb, bits)` | Zero-fills `cb` bytes. |
| `Video_GetScreenShotFolder()` | Returns `""`. |
| `GetFullScreenShowSubunitStatus()`, `GetBestDisplayResolutionForFullScreen()` | Return false. |
| `SetViewportScale()` | Returns its argument. |
| `Restart()` | Sets `restartRequested()`. |
| Everything else | Does nothing. |

### `src/host/applewin_host.h`
`uint32_t ExecuteStep(uint32_t cycles);` is one emulation step, as `ContinueExecution` in `Windows/AppleWin.cpp` does it with video on and without pacing or full-speed handling: `CpuExecute(cycles, true)`, then `g_dwCyclesThisFrame`, `GetCardMgr().Update` and `SpkrUpdate`, then the end-of-frame check that calls `GetFrame().VideoPresentScreen()`. Returns the cycles executed. Both `RunFrames` and `RunRealtime` use it.

### `src/host/applewin_host.cpp`
Provides what `Windows/AppleWin.cpp` used to provide:
- `GetFrame()`, which returns a static `HeadlessFrame`.
- `GetVideo()`, which returns a static `Video`.
- `GetPropertySheet()`, which returns a static `CPropertySheet`.
- Every other symbol `AppleWin.cpp` defined that the linker reports as unresolved, with the same initial values AppleWin uses.

It doesn't modify any AppleWin file.

### `src/host/emulator.h`
AppleWin's state is global, so there's exactly one emulator per process.

```cpp
struct EmulatorConfig {
    std::filesystem::path configIni;               // AppleWin settings file (assigned to g_sConfigFile)
    eApple2Type model = A2TYPE_APPLE2EENHANCED;
};
class Emulator {
public:
    static Emulator& Instance();
    void Start(const EmulatorConfig&);   // headless init (below) + boot; throws std::logic_error if already started
    void Shutdown();                     // safe to call twice; no-op if not started
    void PowerCycle();                   // ResetMachineState() then boot
    void RunFrames(uint32_t frames);     // fast, video on
    void RunRealtime(std::chrono::milliseconds wallTime);  // paced bursts
    uint64_t EmulatedCycles() const;     // g_nCumulativeCycles
    uint64_t PresentedFrames() const;
    FrameView Frame(bool borders = false) const;
    std::string ReadTextRow(int row) const;  // 40-column text page 1 row 0..23, each byte & 0x7F, as ASCII
    const std::vector<std::string>& Messages() const;  // FrameMessageBox calls so far
};
```

- **Precondition:** every method except `Instance`, `Start` and `Shutdown` throws `std::logic_error` if called before `Start`.
- **`Start`** throws `std::runtime_error` if any `FrameMessageBox` call happened during startup. The error message includes the messages.

**`RunFrames(n)`:**
- Runs until `EmulatedCycles()` reaches at least `start + n × NTSC_GetCyclesPerFrame()`.
- Steps are `CpuExecute` calls of at most 1 ms of cycles (1,020 or fewer), mirroring `ContinueExecution`, so the frame check runs as often as AppleWin runs it. Each step calls `CpuExecute(cycles, true)`, then `g_dwCyclesThisFrame += executed`, `GetCardMgr().Update(executed)` and `SpkrUpdate(executed)`.
- After each step it does the frame check from `ContinueExecution`: if `g_dwCyclesThisFrame >= NTSC_GetCyclesPerFrame()` and `!GetVideo().VideoGetVblBarEx(g_dwCyclesThisFrame)`, it subtracts the frame's cycles and calls `GetFrame().VideoPresentScreen()`.
- `RunFrames(0)` does nothing.

**`RunRealtime(t)`:**
- Uses one `BurstBudget(g_fCurrentCLK6502, 1ms)` and a `RealtimePacer`.
- Runs bursts with the same per-step logic as `RunFrames`, waiting for a tick between bursts, until `t` of wall-clock time has passed.

**`Frame(borders)`:** AppleWin's framebuffer is stored bottom-up (`NTSC_VideoInit`), so frames are returned with `strideBytes = -(fullWidth × 4)`.
- `borders = false` gives the 560×384 area inside the border. `topRow` points at row `H − 1 − borderH`, column `borderW`.
- `borders = true` gives the full 600×420 buffer. `topRow` points at row `H − 1`.

**Headless startup order** (taken from `WinMain`, `OneTimeInitialization` and `RepeatInitialization` in `Windows/AppleWin.cpp`):
1. Set `g_sStartDir` and `g_sProgramDir` to the exe's folder, and `g_sConfigFile` to `configIni`. Set `g_nMemoryClearType = MIP_ZERO`, so memory at power-on is deterministic.
2. Call `SetAppleWinVersion` with the version numbers from AppleWin's `version.h`.
3. Run these AppleWin steps:
   1. `KeybReset()`
   2. `GetVideo().SetVidHD(false)`
   3. `ResetToLogoMode()`
   4. `LoadConfiguration(true)`
   5. `SetApple2Type(model)`
   6. `JoyInitialize()`
   7. `VideoSwitchVideocardPalette(RGB_GetVideocard(), GetVideo().GetVideoType())`
   8. `GetFrame().Initialize(true)`
   9. `MemInitialize()`
   10. `SpkrInitialize()`, with `g_bDisableDirectSound = true` so no DirectSound is touched.
   11. `GetCardMgr().Reset(true)`
4. Boot, as AppleWin's `BTN_RUN` handler does from logo mode:
   - If slot 6 holds a Disk II card, call `Boot()` on it.
   - Set `g_nAppMode = MODE_RUNNING`.

**AppleWin startup steps deliberately skipped:**
- `DebugInitialize()`. It calls `Win32Frame::GetWin32Frame`, which throws `std::bad_cast` on `HeadlessFrame`.
- COM, the DirectShow system clock, and DirectSound initialisation.
- Window class and window creation, full-screen setup, hotkeys, and the keyboard hook.
- The About dialog and the old-version check.
- File-type registration, speech, and RIFF/WAV output.
- Command-line slot, card, disk and snapshot handling.

**Shutdown:** call `SpkrDestroy()`, `GetFrame().Destroy()` and `LogDone()`.

### `src/main.cpp` — command line
```
AppleWinHarness.exe --boot-frames <n> [--png <path>]
```
- Starts the emulator with a config INI at `%TEMP%\applewin-harness\<pid>.ini` (the directory is created if needed).
- Runs `n` frames.
- Writes the borderless frame to `<path>` if `--png` is given.
- Prints `sha256 <FrameHash(borderless frame)>` to stdout and nothing else on success; stderr stays empty.
- Shuts the emulator down and deletes the INI.

**Exit codes:**
- `0` — success.
- `2` — bad arguments. Prints usage to stderr.
- `1` — any other failure. Prints the error to stderr.

## Test layout
- **Framework:** doctest 2.4.11, vendored as `third_party/doctest/doctest.h`.
- **Shared emulator:** all emulator tests share one emulator, started on first use by `tests/support/emulator_fixture.h` (`harness::Emulator& StartedEmulator()`) and shut down at process exit.
- **Golden hash:** stored in `tests/golden/m1_boot_120.sha256` (a single line).
- **Timing-dependent tests** go in the doctest test suite `realtime`, so CI can run them separately with `-tse=realtime` or `-ts=realtime`.
